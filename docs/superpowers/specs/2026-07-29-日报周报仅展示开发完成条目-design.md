# 日报/周报仅展示「开发完成」条目

## 背景

当前日报/周报中，需求开发、缺陷修复、其他板块对任务状态的过滤不一致：

- 需求开发使用 `allowedTaskStatuses`（开发完成/测试中/测试完成/任务完成，共 4 种）
- 缺陷修复、其他板块无状态过滤（日期范围内全部展示）

期望调整为：报告展示的完成条目统一只统计「开发完成」或「任务完成」状态，其他状态（测试中、测试完成、进行中等）不在这些板块展示。

## 领域约定

**「开发完成」与「任务完成」等效**：凡是以"已完成"为条件的过滤、计数、判定，两者均视为完成状态。

## 适用范围

日报与周报均适用。

### 日报（buildReportMarkdown）

| 板块 | 过滤规则 | 现状 | 是否变更 |
|---|---|---|---|
| 一、1 需求开发（demands + defectToDemands） | 仅 开发完成/任务完成 | 4 种状态 | ✅ 收窄 |
| 一、1 需求开发 fallback（进行中前 2 条） | 进行中（不变） | 进行中 | ❌ 不变 |
| 一、2 缺陷修复 2.1 pp缺陷（含无效缺陷） | 仅 开发完成/任务完成 | 无过滤 | ✅ 新增 |
| 一、2 缺陷修复 2.2 非pp缺陷（含无效缺陷） | 仅 开发完成/任务完成 | 无过滤 | ✅ 新增 |
| 二、其他（无提交缺陷 + 迁移 + 打包） | 仅 开发完成/任务完成 | 无过滤 | ✅ 新增 |
| 六、目标达成（achievedItems） | 仅 开发完成/任务完成 | 仅 开发完成 | ⚠️ 连带变化（见下） |

### 周报（buildWeekReportMarkdown）

| 板块 | 过滤规则 | 是否变更 |
|---|---|---|

## 连带行为变化

全局扩展 `completedTaskStatuses` 后，以下两处因已使用该集合，行为随之变化：

1. **六、目标达成（achievedItems）**：原本仅包含「开发完成」，现在也包含「任务完成」
2. **缺陷来源信息附加条件**（[generate-report-kf.js:247](generate-report-kf.js#L247)）：原本仅「开发完成」的缺陷附加【缺陷引出人/部门/时间】，现在「任务完成」的缺陷也会附加

依据「开发完成与任务完成等效」的领域约定，这两处变化符合预期。

## 实现策略

采用**渲染时过滤**（方案 A），保护 send-email.js 的抄送逻辑不受影响。

### 改动点

1. **[completedTaskStatuses](generate-report-kf.js#L25)**
   - 现状：`new Set(['开发完成'])`
   - 改为：`new Set(['开发完成', '任务完成'])`

2. **[pushUnique](generate-report-kf.js#L312)**
   - 收集的 item 补充 `taskStatus` 字段（当前未携带）

3. **新增纯函数 `filterCompleted(items)`**
   - 返回 `items.filter(i => completedTaskStatuses.has(i.taskStatus))`

4. **[buildReportMarkdown](generate-report-kf.js#L656)（日报）**
   - 需求开发：`filterCompleted([...demands, ...defectToDemands])`，fallback 逻辑不变（仍取 `topInProgressDemands`）
   - 缺陷修复 2.1：`filterCompleted([...ppDefects, ...ppInvalidDefects])`
   - 缺陷修复 2.2：`filterCompleted([...nonPpDefects, ...nonPpInvalidDefects])`
   - 其他：`filterCompleted(collectUniqueItems(noCommitDefects, migrations, packs))`

5. **[buildWeekReportMarkdown](generate-report-kf.js#L446)（周报）**
   - 需求：`filterCompleted([...demands, ...defectToDemands])`
   - 问题修复：`filterCompleted(defectItems)`
   - [buildWeekSummary](generate-report-kf.js#L422)：缺陷计数改用过滤后的数量

6. **[monthlyDemandProgress.completedCount](generate-report-kf.js#L548)**
   - `allowedTaskStatuses.has(record.taskStatus)` → `completedTaskStatuses.has(record.taskStatus)`
   - 该字段仅用于周报「重点工作」展示，无邮件消费方，采集时改即可

### 不变范围

- [extractDeveloperReportData](generate-report-kf.js#L485) 返回的原始列表（demands/ppDefects/nonPpDefects/migrations/packs 等）不变 → send-email.js 抄送逻辑零影响
- 七、明日工作计划的进行中逻辑不变
- `allowedTaskStatuses`、`inProgressTaskStatuses` 常量不变
- 一、1 需求开发 fallback（topInProgressDemands）不变

## 测试计划

采用 TDD，mocha + chai。新建 `test/generate-report-kf.test.js`（按源文件命名约定，describe 分组）。

### 测试用例

1. **日报·需求开发**：混合状态数据 → 仅输出 开发完成/任务完成 条目，测试中/测试完成 排除
2. **日报·需求开发 fallback**：无完成条目时 → 取进行中需求按计划完成日期排序前 2 条
3. **日报·缺陷修复 2.1/2.2**：仅 开发完成/任务完成（含无效缺陷同样过滤）
4. **日报·其他**：无提交缺陷/迁移/打包 均仅 开发完成/任务完成
5. **日报·目标达成**：包含任务完成条目（连带变化验证）
6. **日报·缺陷来源**：任务完成的缺陷附加来源信息（连带变化验证）
7. **周报·需求 + 问题修复**：仅 开发完成/任务完成
8. **周报·汇总计数**：缺陷计数 = 过滤后条数
9. **周报·重点工作月度进度**：completedCount 仅统计 开发完成/任务完成

### 回归

- [test/report-other-section.test.js](test/report-other-section.test.js) 等现有测试保持通过
- 现有测试 mock 数据需补充 `taskStatus: '开发完成'`，否则过滤后为空导致断言失败
- [test-report.js](test-report.js) 不受影响（extractDeveloperReportData 原始列表未变）

## 风险

- `completedTaskStatuses` 扩展为全局常量，影响目标达成和缺陷来源两处现有行为。已在「连带行为变化」中明确，需用户确认。
